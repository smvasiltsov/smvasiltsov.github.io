# Карточка места посещения · версия 1

Обязательный стандарт для каждого `cardType: "place"`. Отели сохраняют
отдельный шаблон. Музей, парк, район, храм и торговый комплекс используют
одну вёрстку. Категория и подтип не определяют состав HTML.

Данные: `beijing/data/points.json`. Компонент: `place-card.js`.
Контракт: `visit-contract.js`. Стили: `styles/place-card.css`.
Общие поля точки (ID, названия, координаты, категория, подтип, теги,
описание, фотографии, родитель) сохраняются; новое содержание — в `visit`.

## Порядок разделов

1. **Название и тип:** русское и китайское названия, категория, подтип, теги.
2. **Зачем сюда идти:** `visit.summary`, 1–2 предложения с причиной визита.
   Существенную оговорку, меняющую решение о поездке, включать в вывод.
3. **Кратко о посещении:** время на месте, когда лучше идти, часы работы,
   стоимость, бронирование, доступ. Все шесть полей присутствуют всегда.
4. **Фотографии:** общий вид первым, затем детали, подписи и атрибуция.
   При отсутствии фото — сообщение и доступная внешняя галерея с пометкой,
   что для неё нужен интернет. Источники фото не подтверждают условия входа.
5. **Что здесь делать и смотреть:** `description` и 3–5 конкретных пунктов
   `visit.activities`: занятия, участки прогулки, залы или объекты.
6. **Оценка прогулки:** дополнительный `walk`, когда есть все критерии и
   объяснения. Не является рейтингом музея/храма. Его дата не проверяет цены.
7. **Что учесть перед посещением:** `visit.considerations`, важные особенности
   входа, нагрузки, погоды, съёмки и актуальности фото. Пустой блок скрыт.
8. **Как добраться и с чем совместить:** `visit.arrival`, навигация,
   родитель/вложенные объекты, `visit.combineWith`. Показывать адрес,
   станцию и точку старта при наличии сведений. Координата не обязательно
   означает билетный вход. Совместное посещение не создаёт связь `parentId`.
9. **Источники и актуальность:** `visit.provenance`, ссылки и исходная дата
   проверки практических сведений; при отсутствии это указано явно.

## Контракт `visit`

```json
{
  "version": 1,
  "summary": "Короткая причина включить место в поездку.",
  "activities": ["Конкретное занятие 1", "Конкретное занятие 2", "Конкретное занятие 3"],
  "duration": {"status":"estimate","value":"1–2 часа","sources":[],"checkedAt":null},
  "bestTime": {"status":"unknown","value":null,"sources":[],"checkedAt":null},
  "hours": {"status":"unknown","value":null,"sources":[],"checkedAt":null},
  "cost": {"status":"unknown","value":null,"sources":[],"checkedAt":null},
  "booking": {"status":"unknown","value":null,"sources":[],"checkedAt":null},
  "access": {"status":"unknown","value":null,"sources":[],"checkedAt":null},
  "considerations": [],
  "arrival": {"address":null,"metro":null,"start":null,"note":null,"coordinateSource":null},
  "combineWith": [],
  "provenance": {"sources":[],"checkedAt":null,"basis":"existing-project"}
}
```

Статусы практических полей:

- `documented`: записано по источнику. Обязательны текст, ссылка и исходная
  дата проверки. Это снимок сведений на дату, а не гарантия текущих условий.
- `estimate`: авторский ориентир. Допустим только для длительности и
  рекомендации времени визита; цены, расписание и доступ не угадываются.
- `unknown`: не проверено, `value: null`. Не означает бесплатно или без записи.
- `not_applicable`: неприменимо, `value: null`; не подмена непроверенных данных.

Даты — `YYYY-MM-DD` либо `null`. Не заменять неизвестную дату сегодняшним
числом. Для цены указывать валюту, единицу тарифа и отдельные платные части;
для часов — дни, сезон и последний вход, когда известны. Условия, записанные
в предупреждении, по мере проверки переносить и в соответствующее поле.

`provenance.basis: existing-project` — перенос прежних сведений без нового
исследования. `source-review` — новая проверка, требует источника и даты.
Источники координат хранятся отдельно от источников условий посещения.

## Редактирование и проверки

Редактировать канонический `visit`. Старые `note`, `visitNote`, `checked`,
`checkedAt` и общие `sources` сохранены как исходные данные миграции;
новый интерфейс практических разделов их не читает. `description`, `photos`,
`walk`, `hotel` используются напрямую. Сохранять ID и существующие ссылки.

Три занятия должны описывать именно это место. Краткий вывод не повторяет
длинное описание. Не добавлять цены/время/адреса, которых нет в источниках.
Пустые дополнительные блоки скрывать, порядок остальных сохранять.

После изменения данных, HTML, JS или CSS:

```sh
node travel-map/scripts/build-offline.mjs beijing/data/city.json
npm --prefix travel-map run check
```

В браузере проверить обычное место, прогулочный район, место без фото,
вложенный объект и переключение место → отель → место на широком и узком
экране. Проверить галерею и переходы по связанным карточкам.

## Первоначальное приведение к стандарту

Перенесены все 64 места с сохранением описаний и практических предупреждений.
У каждого — краткий вывод и три занятия. Имеющиеся длительности прогулок
сохранены; для остальных написаны авторские ориентиры. Непроверенные
практические поля имеют `unknown`. Даты не заменены датой миграции.
Новая структура не означает нового исследования условий посещения всех мест.
